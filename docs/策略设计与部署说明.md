# 1. 系统目标与边界

LongVol 用 long call 表达 panic 后的方向性凸性反弹，不是 delta-neutral 的纯波动率套利。标的反弹正确仍可能因 IV crush、theta、bid/ask 或成交滑点亏损。

系统解决手动执行中候选遗漏、规则漂移、记账不完整和止损随意变化的问题。它负责：

- 自动粗筛、候选跟踪与失效管理；
- 数据同步、时间戳与完整性检查；
- panic、compression、volume profile、short pressure 与基本面门槛；
- 期权曲面、合约可交易性、保守定价情景与自动仓位状态机；
- 已有持仓的多层退出状态机；
- 次日盘中的执行质量与安全退出检测；
- 模拟/实盘隔离、幂等 DAY 限价单、撤单、订单对账和终态成交回写；
- 配置、特征、信号、账户、订单、成交、持仓生命周期与故障审计。

它刻意不负责：

- 用语言模型或样本内点估计生成 Kelly 胜率；
- 自动换汇，或把 HKD 余额当作美股期权 bankroll；
- 承诺 stop 的成交价格；
- 用当前期权链伪造历史回测；
- 从普通 OI 推断 dealer 净 gamma 方向；
- 让语言模型直接给出买卖或仓位决定；
- 充当高频交易系统或替代 broker 端紧急控制。

## 1.1 三个不同的“生产级”

- 工程生产：可重复运行、幂等、防并发、失败关闭、broker 对账、可审计和可备份。v0.6 以此为目标。
- 策略验证：相同规则在样本外、含成本后仍有稳定正期望。当前需要历史数据验证。
- 自动执行：v0.6 包含刻意收窄的订单层；在 REAL 前仍需完成模拟盘验收、外部 kill switch 与人工 broker 端兜底演练。

# 2. 架构与每日流程

每日主链只有一个入口，所有步骤共用同一 `as_of`：

1. `account-sync` 选择一个明确的美股账户，同步 USD 资金、broker 持仓、当前订单和近 30 日历史订单，并回写已知终态成交。
2. `get_stock_screen` 用价格、市值、5 日跌幅和量比做高召回筛选。
3. 本地计算 20 日平均成交额，合并 `data/tracked.csv`；普通候选 30 天后过期，OPEN 持仓不会过期。
4. OpenD 预检历史 K 线配额，再同步日 K、最多 90 个自然日的 5 分钟 K、卖空数据、Option Screening 和 Option Underlying Rank。
5. Option Screening 获取高 OI 与高成交并集；正常同日任务只刷新可能入选的 Call，盘前补跑则刷新全部保留合约，并只接受 Market Snapshot `update_time` 等于 `as_of` 的合约。Option Underlying Rank 的 IV percentile 只服务冷启动，不写入本地 near-ATM IV 历史。
6. OpenAI 基本面研究只使用 `as_of` 以前资料，并返回结构化 JSON 与来源 URL。
7. `scan` 使用 broker 同步的 USD 资金依次执行数据、panic、stabilization、geometry、short、fundamental、option、自动仓位模式与组合门槛。
8. `exits` 产生确定性退出建议；次日 `intraday-monitor` 只检查执行条件和安全退出，不改变 thesis。
9. SQLite/CSV 保存信号、订单意图、远端状态、终态成交和事件后持仓；提交订单不等于成交。

设计上不再保留截图或图像识别兜底。若 Screener 权限不可用，健康检查失败并停止运行，而不是悄悄切回人工/OCR 数据。

## 2.1 收盘决策与日内执行的边界

收盘引擎决定“这个 setup 是否值得占用资本”，日内模块只决定“冻结后的 setup 现在是否能以合理价格执行”。默认美东 10:00–15:30 才允许次日入场，行情源时间戳不得超过 20 秒；报价缺失、陈旧、单边或 spread 过宽都阻止新仓。

到期风险、标的 hard stop 和时间止损不会仅因 spread 过宽而被否决；权利金止损和结构/期权目标属于价格敏感退出，spread 异常时等待。若没有正 bid，系统告警而不会记录虚假成交。

# 3. 为什么使用顺序门槛

当前不采用加权总分，因为没有足够样本决定权重。总分会允许不应互相补偿的问题被抵消，例如：极差的期权流动性被很高的 panic 分数掩盖，或估值体系已经变化的股票靠技术指标过关。

顺序门槛把策略拆成可证伪假设：

1. 确认价格与交易流错位；
2. 要求独立的波动率或期权压力证据；
3. 等待卖压压缩和反转；
4. 检查上方供给、支撑与目标空间；
5. 排除 short pressure、基本面、期权价格和组合风险问题。

未来有足够逐时点样本后，可以在通过硬门槛的候选中用概率模型排序；数据新鲜度、估值破坏、价差和风险上限仍应保留为 veto。

# 4. 自动粗筛设计

## 4.1 Stock Screener V2

粗筛追求召回率，不在服务器端重现整套策略。默认条件：

| 条件 | 默认值 | 目的 |
|---|---:|---|
| 市场 | 美股 | 固定交易与数据语义 |
| 股价 | ≥ 5 美元 | 减少极低价股噪声 |
| 市值 | ≥ 10 亿美元 | 降低融资/退市与操纵风险 |
| 5 日涨跌幅 | ≤ -8% | 捕捉短期急跌 |
| 当日量比 | ≥ 2.0 | 捕捉异常交易流 |
| 20 日平均成交额 | ≥ 2,000 万美元 | 保证标的基础流动性 |
| 最大结果数 | 200 | 限制下游成本 |

Stock Screener 直接表达前五项并返回价格与 20 日平均成交量；程序再计算平均成交额。60 日 peak-to-current drawdown 仍由本地日 K 严格计算，不依赖供应商筛选器的相似字段。股票层 IV/HV 不在粗筛阶段重复请求，避免引入不参与决策的字段；期权波动率统一从 Option Screening 链面计算。

Stock Screener V2 支持分页，官方限制为同一接口 30 秒最多 10 次。本项目对每类端点独立限速，避免股票筛选、期权筛选与其他行情调用互相误伤。

## 4.2 tracked universe

`data/tracked.csv` 不是永久名单。普通候选以最近一次被 Screener 命中的 `as_of` 为准，超过 `tracked_max_age_days=30` 自动移除；真实 OPEN 持仓始终保留，直到真实 `CLOSE/EXIT` 成交更新持仓文件。

## 4.3 Option Screening 的最小充分并集

只取高 OI 会漏掉当日新出现的保护流，只取高 volume 会丢失稳定的曲面结构。因此每个标的执行两次服务器端查询：

- surface 集：`open_interest ≥ option_surface_min_open_interest`；
- flow 集：`volume ≥ option_flow_min_volume`。

两者按 option code 去重，上限默认为 4,000 个合约。超过上限会停止并报错，避免静默截断。服务端每页最多 200 行；分页和 30 秒 10 次的限速由适配器处理。

Option Screening 只提供当前链面，而且不为每行提供来源日期。正常同日任务先按 DTE、delta、OI、volume 和 spread 初筛，再只对候选 Call 调用 Market Snapshot。纽约 09:00 前的上一交易日补跑会刷新全部保留合约，并只保留 Market Snapshot `update_time` 日期严格等于 `as_of` 的合约；这只是最近完成交易日的有界补跑，不是任意历史回放。

# 5. Panic / dislocation 假设

## 5.1 Panic 不是“跌得多”

普通下跌可能代表盈利能力、融资条件或估值锚永久变化。本策略只寻找短期强制卖出或保护需求集中造成的错位。price-flow 是必要条件，还要至少一个独立确认。

Price-flow 默认要求：

- 60 日回撤 ≤ -20%；
- 5 日回撤 ≤ -8%；
- 最近冲击日成交量 z-score ≥ 1.5；
- 冲击日至少满足：收益 ≤ -5%、gap ≤ -2%、range/ATR ≥ 1.5，或 forced-liquidation proxy。

forced-liquidation proxy 只表示“大成交量 + 大区间 + 靠近日低收盘 + 明显下跌”的组合。日 K 无法识别保证金追缴、赎回或卖方身份，所以日志明确标记为 proxy。

## 5.2 为什么保留 Yang–Zhang

Yang–Zhang 同时利用 open、high、low、close，拆分隔夜跳空、开收盘波动与 Rogers–Satchell 日内区间。在 panic 经常同时出现 overnight gap 与日内宽幅时，它比 close-to-close realized volatility 信息更完整。

它不是下行波动率，也不是买入信号。系统仅把 `短窗 Yang–Zhang / 长窗 Yang–Zhang ≥ 1.25` 与 downside return share ≥ 60% 作为独立确认之一。后续研究必须做 estimator 消融；若没有稳定增量价值，应降级为记录特征而非门槛。

## 5.3 期权 panic 证据

期权压力包括：

- 近 ATM IV 相对前值跳升；
- 25-delta put IV 高于 call IV；
- 近月 ATM IV 高于远月，term structure 倒挂；
- put/call volume 与 put 成交占比异常。

至少两个信号才通过 option panic。成交量没有主动买卖方向，put volume 不能被表述为“已确认大量买入 put”；财报等已知事件也会产生期限结构隆起，必须由基本面模块解释。

## 5.4 Panic 总门槛

`price_flow = true` 且以下至少一个成立：

- Yang–Zhang + downside 确认；
- option panic 确认。

只有这一步通过才进入 `WATCH` 或更高状态，否则 `NO_TRADE`。

# 6. 入场时点：compression 与 reversal

暴跌发生时不立即接刀。`compression` 只能在 `panic_confirmed=true` 后成立，并以最近一个“异常成交量与价格/区间冲击发生在同一根日 K”的 shock day 为锚点。默认至少经过 2 个完整交易日后才开始判断。

卖压耗竭要求：

- shock 后最多 5 个交易日的平均成交量 / shock day 成交量 ≤ 0.85；
- 最近 10 日 ATR / 此前 20 日平均 true range ≤ 0.85，或最近 10 日 realized volatility / 此前 20 日 realized volatility ≤ 0.85；
- 成交量衰减是必选项，ATR/RV 至少一项通过。`volume_ratio`（最近 5 日相对常态）仍保留为诊断值，但不作为 shock 后卖压衰减的替代品。

随后最新日 K 还必须满足：

- 当日 close 高于前一日 close；
- close location ≥ 0.65；
- 当日 low 没有创最近两日新低。

这是一种简单、可解释、fail-closed 的卖压耗竭代理。它不会预测底部，只阻止在压力仍扩张时入场。高成交量负收益本身可能携带流动性冲击信息，因此成交量不是要求低于事件前常态，而是要求在 shock 之后衰减。

研究依据只支持“流动性冲击后的短期反转”和“基本面新闻必须剥离”这两个方向，不支持 0.85 或 2 日为普适最优参数。Nagel（2012）将短期反转收益解释为流动性供给回报；Campbell、Grossman 与 Wang（1993）指出高成交量下跌更可能伴随更高预期收益；Da、Liu 与 Schaumburg（2014）发现无法由基本面现金流新闻解释的下跌更可能短期反转；Cox 与 Peterson（1994）则提醒极端单日下跌后的短期反转可由流动性和 bid-ask bounce 解释，长期表现仍可能较差。当前阈值是待 walk-forward/OOS 消融验证的保守先验：

- https://doi.org/10.1093/rfs/hhs066
- https://doi.org/10.3386/w4193
- https://doi.org/10.1287/mnsc.2013.1766
- https://doi.org/10.1111/j.1540-6261.1994.tb04428.x

# 7. Volume profile、价格真空与目标

生产入场默认要求 panic leg 至少 100 根 5 分钟 K。每根小 K 的成交量均匀分配到它覆盖的价格格，再计算：

- POC；
- 70% value area；
- 局部 high-volume nodes；
- 当前价上方 10% 区间的成交量份额和密度比；
- 当前价到最近 profile 支撑、阻力和目标的 ATR 距离。

价格真空默认要求上方成交量份额 ≤ 25%、上方密度 ≤ 全 profile 平均的 75%、目标空间 ≥ 1 ATR，并且 profile 支撑距离在 0–3 ATR 内。日 K profile 只用于诊断，不能通过 production gate。

冻结目标从最先到达的上方 HVN、VAL、POC 或 material gamma concentration 中选取；都不存在时使用 2 ATR 回退。目标必须至少有 1 ATR 空间。

# 8. Short pressure 与 gamma 的正确语义

## 8.1 卖空数据

FINRA daily short volume 是报告设施中的当日卖空成交量，不是尚未回补的 short interest。系统分别记录：

- short interest 的最近两期存量变化；
- daily short-volume ratio 相对短期/20 日均值的变化。

必须至少一项显示减弱且没有显著恶化，才通过。short interest 默认 21 天内有效，daily flow 默认 4 天内有效；陈旧数据不能通过。

## 8.2 Gamma concentration proxy

普通链面只知道 strike、gamma、OI 和合约乘数，不知道持仓方向或 dealer 对手方。系统计算每个 strike 的：

`abs(gamma) × OI × multiplier × spot² × 1%`

只有单一 strike 占筛选后链面绝对代理总量至少 5% 才视作 material concentration。它可以作为潜在目标/障碍，不能作为确定支撑，也不参与 support gate。由于 Option Screening 刻意截取高 OI 与高成交并集，输出质量标签为 `screened_union_dealer_side_unknown`。

# 9. 基本面研究规则

OpenAI 只做非数值判断层：catalyst、估值体系是否变化、thesis 是否 intact/uncertain/broken。要求：

- 只使用 `as_of` 当日或以前公开的信息；
- 每项关键事实带日期和 URL；
- 优先公司公告、SEC、监管或法院等第一方来源；
- 来源不足、日期不清或内容在截止日后出现时必须 `needs_review=true`；
- 无可核查来源时 confidence 上限为 0.49。

资料默认 7 天内有效，confidence ≥ 0.65 且无需复核才能通过。`catalyst_present` 记录但不是硬门槛；`valuation_regime_break=true` 或 `thesis_status=broken` 是 veto。

# 10. 期权 surface 与合约选择

## 10.1 Surface 门槛

系统从筛选后链面计算：

- 25-delta put-call skew ≤ 20 vol points；
- 远月减近月 ATM IV 位于 -10 至 +15 vol points；
- IV regime percentile ≤ 85%。冷启动必须使用与 `as_of` 完全相同日期的 Moomoo vendor IV percentile；验证模式必须使用至少 60 个先验本地 near-ATM IV 观测计算的分位；
- 近 ATM IV / Yang–Zhang volatility ≤ 2.25。

这些条件避免在恐慌最昂贵或曲面仍严重扭曲时追高 vega。两种 IV 来源必须分栏记录：vendor percentile 不回填 `option_history.csv`，本地序列也不冒充供应商历史。Option Screening 的并集是速度与覆盖面的工程折中；正式研究应记录 chain coverage，若未来发现 gamma/skew 对低 OI strikes 敏感，应提高覆盖而不是调松结论。

## 10.2 合约可交易性

默认选择 call，要求：

| 条件 | 默认值 |
|---|---:|
| DTE | 45–150 天 |
| delta | 0.25–0.45 |
| open interest | ≥ 100 |
| 当日 volume | ≥ 10 |
| spread / mid | ≤ 10% |
| ask / spot | ≤ 15% |
| 报价时间 | 与 as_of 同一天 |

排序偏好：更窄 spread、delta 接近 0.40、DTE 接近 90 天。恢复 `0.25–0.45` 是为了保持原策略的凸性和较低权利金；不再向更低 delta 扩展，因为那会过度依赖更大、更快的反弹。bid 为零、ask < bid、IV/Greeks 无效或报价陈旧都会 veto。

## 10.3 保守情景价格

两种仓位模式都需要期权层面的目标价与止损价。默认用 Black–Scholes 情景：目标标的价为冻结结构目标、目标 IV 假设 crush 15%；止损标的价为冻结 hard stop、止损 IV 假设上升 5%。目标价格再施加保守执行折价。

这些是仓位估算场景，不是可成交保证。若有逐时点历史 surface 或供应商情景，应显式覆盖并版本化。

# 11. 自动仓位模式、Kelly、币种与小账户约束

`config/sizing.json` 只允许 `mode=AUTO`，防止操作员绕过资格检查强制开启 Kelly。模式按标的、按日确定：

| 模式 | IV gate | 仓位 | 信号 |
|---|---|---|---|
| `COLD_START_FIXED_RISK` | 同日 Moomoo IV percentile ≤ 85% | 固定止损风险；不读胜率 | `PILOT_CANDIDATE` |
| `VALIDATED_KELLY` | ≥60 个先验本地 near-ATM IV 观测，分位 ≤85% | 获批概率下界的 1/4 Kelly | `BUY_CANDIDATE` |

冷启动每张合约的冻结损失为 `(P-S)×m+2c`。张数同时受单笔止损风险 2.5%、单笔权利金 5% 和最多 1 张限制；组合也只允许总止损风险 2.5%、总权利金 5% 与 1 个 OPEN 仓位。这不是 Kelly 的替代估计，不需要 `p`，也不产生伪 edge。

验证模式中，期权入场价为 P、止损价为 S、目标价为 T、合约乘数为 m、单边估算费用为 c：

`loss = (P - S) × m + 2c`

`gain = (T - P) × m - 2c`

令获批的保守胜率下界为 p，赔率 b = gain/loss，则 `full Kelly = p - (1-p)/b`。系统使用 1/4 Kelly，单笔止损风险最多 3%、权利金最多 8%、最多 2 张；组合总权利金 20%、总冻结风险 9%、最多 3 个仓位、同一标的 1 个。edge ≤ 0 或不足一张时仍为 `WATCH`。

自动切换并不等于自动批准研究。只有以下条件同时满足才进入 `VALIDATED_KELLY`：

1. 该标的已有至少 60 个严格早于 `as_of` 的本地 IV 观测；
2. `win_probability_lower_bound` 在 (0,1) 内；
3. evidence 标记 `approved=true` 且 `out_of_sample=true`；
4. evidence 的策略版本与运行版本精确一致；
5. 研究文件真实存在且 SHA-256 与配置一致；
6. `sample_end` 不晚于 `as_of`；
7. 至少 60 个样本外观测日与 30 笔完成交易。

任一条件失效会自动回到冷启动，并将 blocker 与 `SIZING_MODE_TRANSITION` 写入日志。系统不会生成概率、批准报告或用 vendor 数据补足本地样本。

仓位基数不是多币种账户净值。`account-sync` 读取 Moomoo 的 USD 资金，默认使用 `usd_net_cash_power`，再应用 `strategy_equity_fraction` 与 USD 2,500 专用资金上限；HKD 不自动换算或计入。部分美股 `STOCK_AND_OPTION` 模拟账户只返回 `us_cash`，不下发逐币种 `cashInfoList.netCashPower`，SDK 因而把 `usd_net_cash_power` 显示为 `N/A`。系统仅在 `SIMULATE` 且默认字段不可用时，以明确的 USD `us_cash` 作为保守、非杠杆的策略资金基数，并把实际字段和回退原因写入账户快照；`REAL` 环境仍严格要求配置字段有效。USD 2,500 冷启动预算约为权利金 USD 125、冻结止损风险 USD 62.50；若整张合约超限，正确结果是 `WATCH`。

所有比例都是风险治理上限，不是已验证的最优值。期权止损不保证成交，长权利仓位最坏经济损失仍可能接近全部权利金。

# 12. 信号状态与完整退出规则

## 12.1 信号

- `NO_TRADE`：panic 不成立，或估值/thesis 已破坏。
- `WATCH`：panic 成立，但 stabilization、geometry、short、fundamental、option、仓位或组合风险未就绪。
- `PILOT_CANDIDATE`：全部门槛通过，但仍在冷启动固定风险模式；仍不是成交。
- `BUY_CANDIDATE`：全部门槛通过且已进入验证 Kelly 模式；仍不是成交。

## 12.2 冻结式开仓字段

真实 `OPEN` 必须保存：entry spot/option price、entry ATR、hard stop、option premium stop、target spot/option price、target source、entry IV/percentile、risk per contract、multiplier、expiry、max holding days 和完整开仓快照。

程序拒绝：重复 OPEN、成交价与冻结入场价不一致、缺止损/目标/IV、初始风险低报、非法日期或重复 broker order id。`REDUCE` 不能减到零；`CLOSE/EXIT` 必须全平。

## 12.3 退出优先级

| 优先级 | 触发器 | 默认动作 |
|---:|---|---|
| 1 | EXPIRY_RISK：DTE ≤ 5 | EXIT |
| 2 | THESIS_BREAK | EXIT |
| 3 | UNDERLYING_HARD_STOP：日内 low 触及冻结止损 | EXIT |
| 4 | OPTION_PREMIUM_STOP：bid 触及冻结权利金止损且 spread 可用 | EXIT |
| 5 | PROFIT_GIVEBACK：曾达 1R 后回落至 0R | EXIT |
| 6 | TIME_STOP：持有达到冻结期限，默认 30 天 | EXIT |
| 7 | DTE_EXIT：DTE ≤ 21 | EXIT |
| 8 | IV_CRUSH：IV 比开仓下降 ≥ 25% 且未达目标 R | EXIT |
| 9 | SHORT_PRESSURE_REACCELERATION 且 spot 低于入场 | EXIT |
| 10 | STRUCTURE_TARGET_REACHED | REDUCE；单张则 EXIT |
| 11 | OPTION_TARGET_REACHED 或 ≥ 1.5R | REDUCE；单张则 EXIT |

标的 hard stop 用开仓 ATR 冻结，不会因当前 ATR 上升而放宽。长仓按可执行 bid 评估，不用乐观 midpoint。单张合约触发减仓条件时直接全平；多张合约的 `REDUCE` 默认建议减半，最终仍以真实成交为准。若期权 bid 缺失，但 expiry、thesis、标的 hard stop 或时间规则已独立确认，`EXIT` 仍保留并附 `missing_inputs`；缺数据不能覆盖安全退出。止损触发价不等于成交价，跳空或流动性不足仍会滑点。

## 12.4 Broker 订单安全

系统只允许 `NORMAL` DAY 限价单。每个意图都有确定性的 client order ID，并写入 Moomoo `remark`；本地和远端双重检查防止重复提交。入场下单前再次验证源时间戳、USD 资金、buying power、spread、live ask 漂移、冻结 option stop、标的止损与 no-chase 条件。broker 层独立复核 `sizing_mode` 与信号状态，并再次执行冷启动 1 张、5% 权利金和 2.5% 止损风险上限，不能只信任 CSV 信号。

默认 `SIMULATE`，且必须选中美股 `STOCK_AND_OPTION` 模拟账户。`REAL` 还必须同时启用 `allow_live_orders=true`、提供 `MOOMOO_TRADE_PASSWORD_MD5`，并在命令中输入完整确认串 `I_UNDERSTAND_LIVE_ORDERS`。下单和撤单不自动重试，因为网络超时不能证明第一次 mutation 没有到达 broker。

报价消失/陈旧、信号过期或标的破坏 setup 时，monitor 撤销已知活动入场单。全部成交或撤单后部分成交等终态会从订单状态读取 `dealt_qty/dealt_avg_price`，并只回写一次。Moomoo 模拟盘没有 deal、fee、cash-flow API，因此模拟费用是明确配置的估计值。

活动中的 hard-risk exit 若不再可成交，会把限价修改到最新正 bid。若 hard exit 出现时已有目标止盈单占用了可卖数量，系统先撤目标单，下一轮再发风险退出，避免两张卖单竞争；目标退出不会在 spread 扩大时追价。

# 13. 安装、配置与运行

## 13.1 前置条件

- Python 3.11+；
- Moomoo OpenD 在本机运行并已登录；
- 美股与 OPRA OpenAPI 行情权限；
- 美股 Moomoo 交易账户；模拟盘需 `STOCK_AND_OPTION`；
- OpenAI API key；
- 系统时间与时区正确。

## 13.2 本机安装

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e '.[openai,moomoo]'

cp .env.example .env
set -a; source .env; set +a

longvol healthcheck --data-dir data --state-dir state --opend --broker --research \
  --trading-config config/trading.json
PYTHONPATH=src python -m unittest discover -s tests -v
```

直接依赖固定为 `openai==3.8.0` 与 `moomoo-api==10.10.7008`。任何升级都必须重跑 Screener 请求、字段映射、分页、限速和全部回归测试。

## 13.3 每日主命令

```bash
python scripts/run_daily.py \
  --config config/strategy.json \
  --sizing config/sizing.json \
  --trading-config config/trading.json
```

默认脚本以纽约当天为 `as_of`，周末及 17:00 前拒绝同日收盘任务。交易所半日市等特殊日期可以人工使用 `--allow-nonstandard-time`。

在下一交易日盘前补跑上一完成交易日，必须在纽约 09:00 前显式指定目标日期：

```bash
python scripts/run_daily.py --as-of 2026-09-09 \
  --config config/strategy.json \
  --sizing config/sizing.json \
  --trading-config config/trading.json
```

补跑模式只接受最近四个日历日内的工作日候选；实际是否为交易日由日线最后日期与 Moomoo 的有日期数据共同验证。Stock Screener V2 仅用于发现候选，不能自行证明历史日期。Option Screening 得到的所有保留合约都会再调用 Market Snapshot；只有 `update_time` 的纽约日期等于 `as_of` 的合约才能进入期权曲面。任何时间戳缺失或最终没有可验证合约时，该股票失败关闭。账户资金使用下单前的真实盘前 USD 快照，不伪造昨日资金；09:00 ET 后不接受“昨日信号 + 今日资金”组合。

直接 CLI：

```bash
longvol daily --as-of 2026-09-08 --start 2025-08-04 \
  --config config/strategy.json --sizing config/sizing.json \
  --trading-config config/trading.json
```

# 15. 失败模式与运行监控

以下情况应停止当天新增信号，但仍优先处理可独立确认的安全退出：

- OpenD 不可达、行情权限不足或 Screener 请求失败；
- 最新日 K 不等于 `as_of`；
- 在纽约 09:00 或更晚启动上一交易日完整补跑；
- 期权 Market Snapshot 缺失或 `update_time` 不等于 `as_of`；
- 期权结果超过配置上限、分页异常或快照为空；
- 关键报价时间不是 `as_of`；
- 冷启动需要的 Moomoo IV percentile 缺失、日期不等于 `as_of` 或超过上限；
- 5 分钟 profile 不足；
- short/fundamental 数据陈旧；
- OpenAI JSON schema、来源或截止日期校验失败；
- SQLite/文件锁失败。
- 账户选择有歧义、币种不是 USD、broker/本地持仓不一致或 buying power 不足；
- quote 无源时间戳、spread 超限、ask 漂移过大或冻结止损已破坏；
- 订单 mutation 返回未知状态、对账失败或终态成交无法回写。

建议监控：run 状态、候选数、gate 失败分布、仓位模式及转换、Kelly blockers、API 延迟/重试、期权覆盖、quote age、spread 分布、撤单率、订单状态滞留、fill slippage、broker/本地持仓差异、未回写成交、日志大小与备份恢复。

# 16. 验证路线与参数治理

## 16.1 最小可信数据

回测必须包含：逐时点 option bid/ask/IV/Greeks/OI、退市股票、拆分和分红、真实交易日历、无前视的基本面时间戳、入场按 ask、退出按 bid、手续费和滑点。当前 Option Screening 只能支持前瞻 paper tracking，不能重建历史链面。

## 16.2 研究顺序

1. 先冻结 v0.6 规则；模拟盘冷启动可以立即收集真实成交与特征，但不得把这段数据伪装成更早的历史。
2. 检查数据失败率和选择偏差，而不是先看收益。
3. 对 price-flow、Yang–Zhang、option panic、compression、profile、short 和 fundamentals 做逐项消融。
4. 用时间序列 walk-forward 和事件/行业分组验证稳定性。
5. 胜率用保守下置信界；Kelly 不接受训练样本点估计。
6. 只在统计、经济意义与执行可行性同时成立时调整阈值，并升级策略版本。

禁止以同一小样本反复优化阈值、删除失败交易或用最终新闻解释历史时点。日志中的 config hash 和 as-of 来源用于防止这种研究污染。

## 16.3 冷启动与验证预热

- 价格数据：首次同步必须取得至少 80 根日 K；panic-leg profile 需要至少 100 根 5 分钟 K。这些真实历史行情可以由 Moomoo 正常回取。
- IV 冷启动：无需等待 60 天；使用 Moomoo `Option Underlying Rank` 在 `as_of` 当天返回的真实 IV percentile。无结果或日期不符就 `WATCH`，不做回填。
- 本地 IV 预热：每次 scan 从当日期权面提取 near-ATM IV，写入 `option_history.csv`。验证模式只读取严格早于当日的至少 60 个本地观测，约 12 个交易周。
- 策略/Kelly 预热：60 个 IV 日期不等于足够交易样本。还需至少 60 个样本外观测日、30 笔完成交易、保守胜率下界、获批标记、真实报告哈希及精确策略版本；稀有 setup 可能需要更久。

因此模拟盘可在数据质量与其他 gates 通过后本周开始；实盘若提前启用，仍只会使用 `PILOT_CANDIDATE` 的小仓固定风险。自动切换的含义是“代码识别已由人和研究流程批准的证据”，不是代码自我批准。

# 17. 上线验收清单

- Stock Screener V2、Option Screening 与 market snapshot 在真实 OpenD 权限下通过冒烟测试；
- 分页、限速、重试和空响应均 fail closed；
- CLI 和文档中不存在截图、图片上传或 OCR 命令；
- 最新日 K 和期权 quote timestamp 与 `as_of` 对齐；
- 单元测试、编译、scan/exits 冒烟通过；
- 开仓冻结字段完整，重复订单与非法仓位变化被拒绝；
- 缺 option bid 时标的 hard stop 仍输出 EXIT；
- 模拟账户选择、USD 资金、DAY 限价单、失效入场撤单、终态部分成交、重启幂等与 broker/本地对账通过故障注入；
- REAL 保持关闭，直到操作员单独启用；缺密码或确认串时任何真实 mutation 都失败；
- SQLite 备份恢复演练通过；
- 冷启动信号只能是 `PILOT_CANDIDATE`，broker 独立复核 1 张、5% 权利金及 2.5% 风险上限；
- Moomoo vendor IV 与本地 near-ATM IV 分开落盘，缺数据不会相互回填；
- 进入 Kelly 前至少有 60 个本地 IV 观测，且 evidence 文件、SHA-256、版本、样本截止日、样本天数、完成交易数和批准状态全部通过；
- 每次模式选择和转换均可从 SQLite 复原；
- 完成模拟盘故障验收后才启用 REAL；策略证据不足时即使 REAL 也保持冷启动限制。
